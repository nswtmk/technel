# 音読装置

執筆中の原稿を声に出して聞き、引っかかった文にその場で朱を入れるための道具。
単一の HTML ファイルで動く。ビルドも外部ライブラリもサーバも要らない。

## 置き場所

https://nswtmk.github.io/technel/ondoku/

technel のトップページ（https://nswtmk.github.io/technel/）からも開ける。
`noindex` を入れてあるので検索には出ない。

iPhone は 共有 → 「ホーム画面に追加」でアプリとして置ける。
本体一式はサービスワーカーが控えるので、二度目からは電波がなくても開く。
読み込んだ原稿と朱入れは端末の IndexedDB に残るので、地下でも山でも読み上げられる。

## 使いかた

1. 上の URL を開く（https で開くこと。Web Speech API は http では動かない）
2. 「原稿を読み込む」から `.md` / `.txt` / `.docx` を渡す。パソコンなら画面に落としてもよい
   ファイルを選べない端末では「本文を貼り付ける」から直接貼る
3. 「第一章を読み上げて」と指示するか、目次から章を選ぶ
   章の右の `▸` を押すと、その章の節・項が下に開く。押せばそこから読み始める
4. 目次には字数が並ぶ。上に原稿全体、各行にその見出しの持ち分

| 操作 | |
| --- | --- |
| `Space` | 再生／停止 |
| `←` `→` | 一文ずつ移動 |
| `M` | いま読んでいる文に朱を入れる |
| 文をクリック | そこから読み直す |
| `+` `-` | 速さを一段ずつ上げ下げ |
| 左の柱 | 章内の位置と朱の分布。点を押すとその文へ戻る |

指示として通る言い回し: 第一章／3章（漢数字・算用数字）、章名の部分一致、節・項名の部分一致、
次の章、前の章、続き、最初から、もう一度、止めて、ゆっくり、速く、1.5倍。
マイクボタンで同じ指示を声でも渡せる（ja-JP）。

速さは 0.5〜3.0 倍。下段の `×1.0` を押すと一段ずつ速くなり、上限まで行くと最初に戻る。
細かく決めたいときは「声と速さ」のつまみか、その下の段ボタンで。

## 作りの要点

- **原稿の取り込み** `.docx` は zip を自前で開き `DecompressionStream('deflate-raw')` で
  `word/document.xml` を展開する（mammoth 等の外部ライブラリを使わない）。
  もっとも浅い見出しを章とし、それより深い見出しは節として本文に含める。
  Word の「表題」スタイルと、はじめに・あとがき等で始まる章は前付けとして番号から外れる。
  目次の「整える」で章ごとに切り替え・削除ができる。
- **ファイル選択** `accept` 属性は付けない（iOS / Android が `.md` を選べなくなるため）。
  input は `display:none` にせず `opacity:0` でボタン全面に重ねる。
  拡張子の判定は JS 側でおこない、読めない形式は黙って失敗せず画面に理由を出す。
- **iOS** 利用者の操作と同じ流れの中で一度 `speak()` を通してから発話する
  （`pointerdown` / `touchstart` で解錠）。章送りは `setTimeout` を挟まず
  `onend` の中で同期的に次章の発話へ入る。
- **Chrome** 15秒前後で合成が打ち切られるため 9秒ごとに `pause()`→`resume()`。
  Safari ではこの手当てが発話を壊すので入れない。
  発話が黙って落ちたときのための見張りを別に置いてある。
- **字数** 数えるのは本文だけで、見出しの文字は分量に入れない。
  節の字数はその下の項をひっくるめた数にする（でないと項を持つ節が痩せて見える）。
  最初の見出しより前の本文は「章のはじめ」として一行に出す。
  こうすると節の字数を足すと章に、章を足すと原稿全体にきっちり届く。
- **節・項** 章より深い見出しは本文の中に置いたまま、目次からその文番号へ飛ばす。
  文番号は章の頭から `splitSents` で数え直すので、目次でその章を開いたときに一度だけ数えて控える
  （`secCache`）。章を消したり原稿を入れ替えたら控えは捨てる。
  同じ章の中で飛ぶときは組み直さず、読んでいる位置だけ動かす。
- **速さ** 発話ごとにしか変えられないので、変えたらいま読んでいる文を作り直す。
  ただしつまみを動かしているあいだ作り直し続けると `cancel()`→`speak()` が連射になり、
  iOS では合成器がそのまま黙る。手が止まって 220ms 経ってから一度だけ作り直す。
- **保存** IndexedDB に章ごとの鍵で保存する（`doc:ch:0`, `doc:ch:1` …）。
  一つの鍵に原稿全体を入れないので大きな原稿でも溢れない。
  IndexedDB が使えない環境では localStorage に落ちる。
  画面を離れるときに書き残しを書き切る。

## 見た目

墨・藍・浅葱・朱の四色。本文は明朝、UI はゴシック。
いま読んでいる文には浅葱の淡い地を敷き、左に細い罫を出す。
朱は朱入れにしか使わない。

## 確かめたこと

Chromium で通しの動作確認（19項目）が通っている。
実原稿（.docx 4.8MB / 約19.6万字）で、読み込み 0.2秒、
最大の章（47,451字・1,322文）の描画 0.4秒。
電波を切って開き直しても、原稿と朱入れが残ったまま開くことを確かめてある。
